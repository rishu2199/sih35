I have already built this project using AI/vibe coding. The **functionality and core features are mostly implemented**, but the current UI is poor, cluttered, inconsistent, and looks AI-generated.

I will upload **screenshots/photos of each tab/page of the existing application**.

Your job is to **deeply analyze the screenshots and redesign the UI professionally**, while preserving the existing functionality, data, workflows, APIs, and business logic unless a UI change genuinely requires a small frontend adjustment.

---

# PRIMARY OBJECTIVE

Transform the current application into a UI that feels:

* Modern
* Clean
* Simple
* Professional
* Human-designed
* Easy to understand
* Easy to navigate
* Visually consistent
* Production-ready
* Suitable for a real company/product
* Not overloaded with unnecessary information

The goal is **not to make the UI flashy**.

The goal is to make the UI **simple, intuitive, polished, and useful**.

Think like a world-class product designer building a real production application, not like an AI generating a generic dashboard.

---

**Do not blindly preserve bad UI decisions simply because they already exist.**

Preserve the **functionality**, but improve the **presentation, hierarchy, wording, layout, interaction, and usability**.

---

# DESIGN PHILOSOPHY

Follow these principles throughout the entire application.

### 1. SIMPLICITY FIRST

Remove anything that does not help the user accomplish the task.

Avoid:

* unnecessary cards
* unnecessary descriptions
* repetitive labels
* excessive text
* decorative sections
* duplicate information
* unnecessary tooltips
* unnecessary icons
* excessive badges
* meaningless statistics
* repeated headings
* giant empty containers
* excessive form fields
* unnecessary confirmation UI

Every element should have a clear purpose.

---

### 2. HUMAN-WRITTEN UI

Rewrite awkward AI-generated wording.

Do NOT use unnecessarily complicated phrases such as:

* "Initiate Comprehensive Analysis"
* "Proceed with Document Processing"
* "Utilize Advanced Filtering Capabilities"
* "Data Management & Processing"
* "Operational Performance Overview"

Prefer natural language such as:

* "Analyze"
* "Generate Report"
* "Upload Document"
* "Search"
* "Filter"
* "Performance"
* "Documents"
* "Reports"

Headings should be **short, natural, and immediately understandable**.

Use language a normal human product team would write.

---

# HEADINGS

Make headings concise.

Bad:

"Comprehensive Institutional Accreditation Performance Monitoring Dashboard"

Better:

"Accreditation Overview"

Bad:

"Upload and Manage All Supporting Documentation and Evidence"

Better:

"Documents"

Bad:

"Generate Comprehensive Accreditation Documentation"

Better:

"Generate Report"

Use:

**Title → short**
**Subtitle → only when genuinely useful**
**Section heading → descriptive**
**Button → action-oriented**

Do not write a paragraph when 2–6 words are enough.

---

# LAYOUT

Use strong visual hierarchy.

Prioritize:

1. Page title
2. Important information
3. Primary action
4. Supporting information
5. Secondary actions

The user should understand the page within a few seconds.

Use generous but efficient spacing.

Do not make every section look like a separate card.

Not everything needs:

* a border
* a background
* a shadow
* a rounded container

Sometimes simple text + spacing is better.

---

# REMOVE UNNECESSARY BOXES

This is extremely important.

If multiple fields/cards are currently enclosed in separate boxes but belong together, combine them.

Avoid the common AI-generated pattern:

[ Box ]
[ Box ]
[ Box ]
[ Box ]

Instead create a clean composition with sections and spacing.

Use cards only when they actually improve organization or usability.

---

# FORMS

Simplify forms aggressively.

For every input field ask:

**"Does the user really need to see this field at this moment?"**

If not:

* remove it
* combine it
* make it optional
* move it into an advanced section
* use sensible defaults
* use dropdowns/selectors where appropriate

Avoid giant forms with many fields visible simultaneously.

Group logically related fields.

Example:

### Basic Information

Name
Department
Year

### Documents

Upload
Category
Status

Do not create unnecessary nested containers around every field.

---

# NAVIGATION

Review the entire navigation structure.

Make sure:

* navigation labels are short
* related pages are grouped
* icons are consistent
* active state is obvious
* unnecessary menu items are removed
* navigation does not overwhelm the user

Do not create navigation items merely because functionality exists somewhere in the backend.

Organize the navigation around **what users actually need to do**.

---

# DASHBOARD DESIGN

If a page is a dashboard:

Do NOT automatically create 10–20 statistic cards.

Show only the most useful information.

Prefer something like:

**Overview**

Total Documents     Pending     Completed

Then:

Recent Activity

Recent Documents

Quick Actions

Keep the dashboard focused.

A dashboard should answer:

**"What is important right now?"**

not:

**"How much information can we display?"**

---

# BUTTONS

Reduce the number of buttons.

Every page should have a clear primary action.

Use hierarchy:

**Primary action**
→ filled/prominent

**Secondary action**
→ subtle/outline

**Tertiary action**
→ text/icon

Avoid making every button visually equal.

Examples:

Instead of:

[Save] [Submit] [Process] [Continue] [Generate] [Export] [Download]

determine the actual primary action and simplify the UI.

---

# TABLES

If a table exists:

* show only important columns
* shorten column names
* align data correctly
* make rows easy to scan
* use appropriate status indicators
* avoid unnecessary actions in every row
* use a compact action menu when appropriate

Do not create excessively wide tables.

---

# COLORS

Use a restrained color palette.

Prefer:

* neutral background
* clear text hierarchy
* one primary brand/accent color
* subtle success/warning/error colors

Do not use many random colors.

Do not make every section colorful.

Color should communicate meaning, not decoration.

---

# TYPOGRAPHY

Create a clear hierarchy between:

* page title
* section title
* body text
* labels
* metadata
* buttons
* table content

Avoid:

* oversized headings
* excessive bold text
* too many font sizes
* long uppercase headings

Typography should feel consistent throughout the entire application.

---

# ICONS

Use icons only when they improve recognition or reduce text.

Do not add icons just for decoration.

Use one consistent icon library/style.

Avoid mixing multiple icon styles.

---

# RESPONSIVE DESIGN

Make the redesigned UI responsive for:

* desktop
* laptop
* tablet
* mobile

Do not simply shrink the desktop layout.

Reorganize components intelligently for smaller screens.

Ensure:

* buttons remain usable
* tables handle overflow properly
* forms remain readable
* navigation works correctly
* spacing remains appropriate

---

# ACCESSIBILITY

Maintain good accessibility.

Ensure:

* sufficient contrast
* readable text
* visible focus states
* meaningful button labels
* proper form labels
* keyboard-friendly interactions
* appropriate aria labels where needed

Do not sacrifice usability for visual appearance.

---

# CONSISTENCY ACROSS ALL TABS

This is critical.

When I upload multiple screenshots, do NOT redesign each page independently.

Create a **single cohesive design system**.

Maintain consistency for:

* typography
* colors
* spacing
* buttons
* cards
* inputs
* tables
* badges
* navigation
* modals
* dropdowns
* empty states
* loading states
* error states

A user should feel that every page belongs to the same product.

---

# DO NOT BREAK FUNCTIONALITY

IMPORTANT:

Do NOT unnecessarily modify:

* backend logic
* API calls
* database structure
* authentication
* business rules
* existing workflows
* existing functional components

First understand the existing implementation.

Make UI/frontend changes wherever possible.

If a component needs structural modification, preserve its existing behavior.

---

# DO NOT INVENT FEATURES

Do not add random features simply to make the interface look impressive.

Do not add:

* fake analytics
* fake data
* unnecessary AI buttons
* unnecessary charts
* unnecessary notifications
* unnecessary dashboards
* unnecessary settings
* unnecessary filters
* unnecessary animations

Only introduce a new component when it clearly improves usability.

---

# ANTI-AI-GENERATED UI RULE

The final interface must NOT look like a typical AI-generated dashboard.

Avoid the common AI design pattern of:

* excessive rounded cards
* huge gradients
* excessive glassmorphism
* unnecessary glowing effects
* random colorful icons
* oversized typography
* excessive shadows
* excessive pills
* too many statistic cards
* giant hero sections
* repetitive containers
* decorative charts with little value

The result should look like a **real product designed by an experienced human UI team**.

---

# CONTENT CLEANUP

Rewrite the visible UI copy wherever necessary.

Remove:

* redundant descriptions
* unnecessary helper text
* repeated information
* technical jargon
* obvious statements
* overly formal wording
* unnecessary subtitles

Keep text only when it improves understanding.

Example:

Instead of:

"Here you can manage, upload, review, and organize all your institutional documents and supporting evidence."

Use:

"Manage your documents."

Or simply:

"Documents"

---

# USER EXPERIENCE TEST

After redesigning each page, mentally test:

### 3-second test

Can a new user understand what this page is for within 3 seconds?

### Primary-action test

Is the main action obvious?

### Scan test

Can users quickly scan the important information?

### Clutter test

Can anything be removed without reducing functionality?

### Consistency test

Does this page visually match the other pages?

### Human test

Does this look like a real professional product rather than AI-generated UI?

If the answer is no, simplify again.
